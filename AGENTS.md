## OVERVIEW

Folia compatibility patch layer for AdvancedEnchantments Minecraft plugin. Decompiles original JAR → applies scheduler migration patches → repackages as fat JAR. Stack: Java 25, Gradle, Vineflower decompiler, Paper/Folia API.

## CONVENTIONS

- **Version auto-detection**: `build.gradle.kts` parses version from `libs/AdvancedEnchantments-<VER>.jar`. Exactly 1 JAR must exist.
- **3-layer fat JAR**: Original classes → patched class overrides → resource overrides. `plugin.yml` gets `folia-supported: true` auto-injected via `tools/scripts/inject-folia-support.sh`.
- **Patch numbering**: Sequential (`NNNN-` prefix), auto-generated by diff. Filename = `<NNNN>-<ClassName>.patch`. **Never hardcode patch numbers in docs** — reference by filename only.
- **Patch headers**: `From`, `Subject`, `AE PATCH REASON`, `AE PATCH FIX`, `AE PATCH RISK` — auto-restored from old patches on regenerate.
- **Zero Maven repos**: All deps in `libs/` as flat JARs. No external repository downloads.
- **No Lombok in patched code**: Decompiled Lombok annotations (`@Generated`, `@AllArgsConstructor`) are stripped — constructors written explicitly.
- **Thread safety**: Patched files use Folia API only (`getGlobalRegionScheduler`, `getRegionScheduler`, `getAsyncScheduler`, `getScheduler`). No `Bukkit.getScheduler()` or `SchedulerUtils` in patched files.
- **Scheduler migration status**: `SchedulerUtils` class stripped (throws `UnsupportedOperationException`). Any file still calling `SchedulerUtils.*` from unpatched `.class` (inside JAR, no patch file) will CRASH at runtime on Folia. Hook files (`ItemsAdderHook`, `McMMOHook`, `MythicMobsHook`) excluded from migration by design.
- **Utility classes**: `SchedulerUtils` is stripped to bare utility (private constructor, throws `UnsupportedOperationException`). `FoliaScheduler` has `isFolia` flag + `checkFolia()`.
- **`set -euo pipefail`** in all shell scripts.
- **Script paths resolve from `$SCRIPT_DIR`**, no hardcoded absolute paths.
- **3 scripts only**: `decompile_src.sh` (jar → decompiled), `apply_patches.sh` (apply all), `generate_patches.sh` (single or bulk generation).

## PATCH WORKFLOW

```
src-patched/  →  generate_patches.sh  →  patches/*.patch  →  ./gradlew clean build
```

1. Edit files in `src-patched/` only
2. Run `bash tools/scripts/generate_patches.sh` — saves old headers, generates fresh diffs
3. Build: `./gradlew clean build`
4. Deploy: `./gradlew deploy`

## ANTI-PATTERNS (THIS PROJECT)

- **Never edit `.patch` files directly** — always edit `src-patched/` then regenerate
- **Never edit `src-decompiled/`** — read-only reference copy
- **Never use `Bukkit.getScheduler()`** — Folia-incompatible, use `getGlobalRegionScheduler`/`getRegionScheduler`/`getAsyncScheduler`
- **Never have 0 or >1 AE JAR in `libs/`** — build fails with clear error
- **Never use Maven/other repos** — all dependencies local in `libs/`
- **Never suppress type errors** with `@ts-ignore`/`as any` (TS patterns don't apply; for Java, no `@SuppressWarnings` on real issues)
- **Never patch hook files** (`ItemsAdderHook`, `McMMOHook`, `MythicMobsHook`) unless explicitly requested — excluded by design.

## NOTES

- `src-decompiled/` and `src-patched/` are gitignored — not in version control. Only `patches/`, `resources/`, `tools/`, `docs/`, and build config are committed.
- Patches-backup.zip in project root is also gitignored.
- Decompiled code includes Lombok-generated noise (`var1`, `var2` params). Patches clean these to descriptive names.
- Some decompiled files have raw type warnings (e.g., `new ArrayList()` without diamond) — pre-existing from decompiler, not introduced by patches. Build still passes.
